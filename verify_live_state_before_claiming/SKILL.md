# Verify Live State Before Claiming

## Check the live state before you claim a result

- Open the live account page, order page or site before you say a purchase, a migration or an ownership is complete.

- Read the order status on the page itself and name the exact state you see, such as cart staged, card saved, order placed, order confirmed or domain active.

- Treat a saved card or a staged cart as not bought, and treat a processing order as not yet live.

- Follow a live URL through its redirect before you prescribe a migration, a Change of Address or a re-upload, and say what the redirect actually does.

- Check the account that holds the asset before you say a domain or a site belongs to the user, and name the account when you report ownership.

- Re-check the live state in the same run when an earlier claim came from memory or from a previous run, and never reuse a past claim as proof.

## Correct a premature claim in the same run

- Correct the claim in the same run when a live check contradicts it, and name the claim you are taking back in plain words.

- Say what the user should not do on the basis of the wrong claim, such as skipping an upload or treating a domain as owned.

- Record the corrected state with the date of the live check so a later run re-checks instead of repeating the old claim.

- Do not repeat the corrected claim in a later run without a fresh live check.

## Name the source and the check you ran

- Name the page or URL you opened and the state you saw there before you report a purchase, ownership or migration outcome.

- Say plainly when a check is blocked and name the blocker and the step that would unblock it instead of reporting the outcome as if the check had run.

- Keep the claim, the check and the date together in one line when you save the state for a later run.

## Alternatives for better results

- Ask the user to paste the order confirmation or a screenshot when the account is blocked, and quote from that confirmation with its date named.

- Check the cheapest live signal first, such as the public URL or the order page, before you open a full account session.
